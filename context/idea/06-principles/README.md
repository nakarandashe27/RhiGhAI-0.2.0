# Принципы RhiGhAI

## Неподвижные правила MVP

1. **Модель предлагает — детерминированный исполнитель решает.** Codex возвращает TaskPlan; JSON Schema и семантический валидатор допускают только известные операции.
2. **Один ответ — один host и одна отменяемая транзакция.** Rhino и Grasshopper никогда не изменяются одним ответом одновременно.
3. **Selection и ownership ограничивают власть.** Существующие объекты меняются только по явному запросу и среди текущего выделения; созданные разговором объекты могут обновляться по локальным ownership-записям.
4. **Долгий диалог не отменяет свежую проверку.** Перед каждым commit повторно проверяются документ, target и fingerprint релевантных объектов.
5. **Rhino остаётся рабочим.** Codex работает асинхронно; нативный commit короткий; Stop прерывает ожидание или откатывает после текущего неделимого вызова.
6. **Результат должен оставаться редактируемым.** В Rhino это нативные объекты, в Grasshopper — живой параметрический компонент с типизированными входами.
7. **Узкий реестр лучше широкой магии.** Новая операция появляется только вместе со схемой, валидатором, исполнителем, C#-представлением и тестами.
8. **Пользователь видит правду.** Лента показывает стадии, попытки, план/эквивалент C#, ошибки и итог, не создавая иллюзию инженерной проверки.
