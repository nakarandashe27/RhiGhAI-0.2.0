# Расходы и ресурсные бюджеты

Личный MVP не имеет backend, базы, hosting, email, платежей и собственной OpenAI API billing. ChatGPT/Codex entitlement принадлежит пользователю; RhiGhAI не обещает конкретную квоту или цену.

## Денежные ресурсы

| Ресурс | Цена | Объём в месяц | Итого |
|---|---:|---:|---:|
| ChatGPT account | Внешняя существующая подписка пользователя; точный тариф не задаёт RhiGhAI | По лимитам account | 0 дополнительной платы RhiGhAI |
| OpenAI API | Не используется | 0 | 0 |
| Hosting/database/telemetry | Не используются | 0 | 0 |
| Local storage | Входит в диск пользователя | runtime + capped logs/transcripts | 0 |
| Code signing | Не приобретено для личного MVP | 0 до публичного релиза | 0 сейчас; публичный Yak заблокирован до решения |
| Yak publication | Инструменты McNeel | После MVP | 0 в MVP |

Если clean-machine gate показывает, что без доверенной подписи first run невозможен, личный installer остаётся локальным development artifact, а внешний релиз не объявляется до приобретения сертификата. Цена сертификата не выдумывается и проверяется перед покупкой.

## AI-профиль

| Задача | Модель | Максимум | Оптимизация |
|---|---|---|---|
| Создать/исправить TaskPlan | Выбранная пользователем из model/list | prompt 16k chars; snapshot 64 KiB; graph 64 nodes; общий timeout | compact typed context, outputSchema, no full geometry |
| Repair | Та же выбранная модель/effort | retry 1–5 внутри общего deadline | fresh delta snapshot, machine error, stop identical pair |
| Account/models/usage | Не LLM | один refresh task | cache до account event/manual refresh |
| GH recompute | Не LLM | host budgets | algorithm выполняется локально без Codex |

RhiGhAI не переключает пользователя на «дешёвую» модель сам: доступный catalog и reasoning efforts динамические, а billing/entitlement контролирует ChatGPT. UI показывает только данные account/rateLimits/usage, которые реально вернул app-server, и не вычисляет рублёвую стоимость.

## Производительные бюджеты

- Panel interaction/Stop acknowledgement: <100 ms без host mutation.
- Selection summary debounce: 250 ms.
- Schema + semantic validation: цель <2 s, обычно значительно меньше.
- UI-thread commit/solve budget: цель ≤2 s; capability benchmark может запретить операцию раньше.
- Один активный Codex turn на document; один managed process на Rhino process.
- Rolling logs: 100 MiB cap на user profile; старше 30 дней очищаются, кроме unresolved journal.
- Runtime disk size и installer size: измеряются Codex runtime gate и фиксируются в manifest; значение не предполагается.

## Сигналы перерасхода

- Snapshot часто упирается в 64 KiB.
- Retry success после первой попытки низок, а median latency растёт.
- Logs регулярно достигают cap.
- Один Rhino process создаёт несколько Codex processes.
- Пользователь видит usage limit чаще успешного результата.

Реакция: сузить snapshot/capabilities, исправить contract/prompts, классифицировать non-repairable errors; не скрывать расход и не обходить лимит аккаунта.
