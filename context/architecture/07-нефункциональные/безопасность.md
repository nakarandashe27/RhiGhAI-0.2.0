# Безопасность

## Модель угроз

RhiGhAI локален, но не offline: он отправляет prompt и минимальный snapshot выбранному провайдеру — ChatGPT через Codex либо OpenAI-совместимому API по ключу пользователя. Главные активы — Rhino/GH document state, проектные metadata, ChatGPT session, local mappings/journals и executable trust chain.

Недоверенные источники: пользовательский prompt, document literals, ответ любого провайдера, downloaded runtime, late/out-of-order protocol events и любые persisted files после crash.

## Секреты и вход

- Ключ API-провайдера принимается только в настройках, хранится зашифрованным DPAPI (CurrentUser) в отдельном файле и никогда не попадает в settings.json, transcript, logs или diagnostic bundle; в UI видны последние 4 символа.
- Access/refresh tokens и cookies RhiGhAI по-прежнему не принимает, не логирует и не копирует — они остаются внутри Codex.
- Managed ChatGPT OAuth запускает официальный app-server; browser flow и device-code fallback приходят из account/login/start.
- Codex хранит/refresh tokens в isolated Codex home под ACL текущего Windows user.
- UI хранит только AccountSnapshot: auth mode, display label, plan type и доступную rate-limit summary.
- Auth URL и loginId redacted из logs. Logout выполняется account/logout и не удаляет геометрию.

## Проверка опасной тройки

Все три ноги присутствуют:

1. **Личные/проектные данные:** prompt, object/layer names, bounds и references.
2. **Ненадёжное содержимое:** names, user strings и GH text могут содержать prompt injection.
3. **Отправка наружу и локальное действие:** snapshot уходит в ChatGPT, plan влияет на Rhino/GH.

Разделение обязанностей:

- **Читающий агент — Codex:** получает instruction и typed/literal data раздельно, работает без RhiGhAI tools, apps, MCP, skills, dynamic tools и write permissions; возвращает только TaskPlan.
- **Действующий агент — deterministic executor:** не видит свободный текст Codex, а получает только прошедший strict parsing, semantic validation, permissions, budgets и stale checks canonical graph.

Даже allowlisted plan может неверно понять намерение, поэтому критическая ambiguity axes/plane/units завершается уточнением, а immediate Undo rate входит в продуктовые сигналы.

## Изоляция Codex process

- Exact pinned official binary, publisher identity и SHA-256.
- Empty private cwd, isolated Codex home, environments empty.
- approvalPolicy never; read-only permission profile; permission requests отклоняются.
- Никаких local file/image inputs, runtime workspace roots и project skills.
- Любой shell/file/tool item прерывает turn и делает plan invalid.
- Prompt запрет использовать tools является только defence-in-depth, не security boundary.
- Conformance gate проверяет filesystem before/after и protocol trace закреплённой версии.

Официальная app-server документация поддерживает managed ChatGPT login, outputSchema, read-only permission profiles, approval policy и interrupt: [Codex app-server](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md). Из-за experimental surface поведение подтверждается fixture, а не предполагается.

## Проверка прав

- Модель не выдаёт разрешения сама себе.
- Host target, selection и ownership зафиксированы TurnRequest до генерации и проверяются перед commit.
- Existing object mutation: только explicit intent + current selection.
- Owned mutation: только current conversation + matching fingerprint.
- Unsupported/delete/unselected/mixed-host/arbitrary-code fail-closed.
- Матрица: [права-доступа.md](../02-ядро/права-доступа.md).

## Лимиты

- Один active turn и один commit lease на document.
- Prompt ≤16 000 chars; selected refs ≤100; layers catalog ≤200.
- Graph nodes ≤64; copy output objects ≤100; Boolean inputs ≤8 и faces budget задаётся capability fixture.
- Retry 1–5, timeout 30–600 s, одинаковый plan/error не повторяется.
- Codex protocol input/output size caps проверяются до allocation.
- GH algorithm имеет node/operation/preview geometry budgets.

## Целостность host

- Prepare не меняет document.
- Durable journal записан до BeginUndoRecord.
- UI-thread commit повторно проверяет identity/fingerprint/cancellation/lease.
- Rollback выполняется только для собственного подтверждённого Undo record в том же callback.
- Crash/unknown journal блокирует новые mutations; blind Undo после restart запрещён.
- GH update сохраняет component/ports/wires и верифицирует solution до success.

## LocalAppData

- Paths не формируются model/user input; reparse targets наружу запрещены.
- User-scoped mutex + generation check предотвращают lost update двух Rhino processes.
- Checksums, backups и quarantine разделены по store.
- Runtime directories immutable; activation manifest меняется атомарно.
- Diagnostic bundle удаляет credentials, auth URLs, full prompt, geometry payload и полный path.

## Журнал действий

С timestamp/correlation id записываются: plugin/runtime versions, document key hash, conversation/turn/attempt, trigger, state transition, model/effort id, snapshot counts, plan/graph hash, validation codes, commit journal phase, Undo identity, created/modified counts, retry/stop/error и durations. Свободный model reasoning и geometry payload не логируются.

## Supply chain и установка

- Source URL, license/redistribution, publisher и SHA входят в signed manifest.
- Staging не активируется до conformance test.
- Defender/SmartScreen не отключаются и Mark-of-the-Web не обходится скрыто.
- Public package требует Authenticode и Yak clean-machine validation.
- Dependency versions pin; build создаёт SBOM/third-party notices и compat.exe report.

## Что сознательно не защищаем в личном MVP

- От администратора Windows или malware в том же user profile.
- От повреждённого/скомпрометированного Rhino host.
- От раскрытия смысла prompt самой службе ChatGPT: пользователь должен понимать, что task отправляется OpenAI.
- От инженерно неверного, но геометрически валидного результата; RhiGhAI не расчётный инструмент.
