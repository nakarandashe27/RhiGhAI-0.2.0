# Триггеры и режимы выполнения

| Триггер | Тип | Что делает | Лимит времени | Защита от дублей | При сбое |
|---|---|---|---:|---|---|
| Загрузка RHP | host event | Регистрирует panel/GHA services, читает settings, запускает recovery/self-test | 3 с foreground; остальное async | process singleton | Записать; открыть Rhino без AI |
| Открытие панели | действие пользователя | Создаёт/привязывает ViewModel и свежий selection summary | 1 с | один panel instance | Показать локальную ошибку |
| Refresh connection | действие пользователя | Проверяет runtime, account, models, usage и protocol compatibility | 30 с async | один refresh task | Показать точный слой сбоя |
| Install Codex | действие пользователя | Скачивает pinned asset, проверяет SHA, атомарно переключает runtime | 10 мин async | install lock + partial marker | Удалить staging, сохранить last-known-good |
| Login/Logout | действие пользователя | Запускает/cancel browser OAuth либо account logout | 10 мин async | loginId | Не retry; показать auth error |
| Send | действие пользователя | Замораживает TurnRequest и запускает turn state machine | setting timeout, 30–600 с | один active turn на document | Классифицировать; repair либо завершить |

| Stop | действие пользователя | Cancel login/turn; ставит cancellation barrier перед следующим native call/commit | UI <100 мс | idempotent cancellation token | Не retry; rollback текущей попытки |

| Repair requested | внутреннее событие | Отправляет fresh snapshot + machine error в тот же thread | общий timeout; max 1–5 | plan/error hash | Стоп при повторе пары |

| Save and close settings | действие пользователя | Валидирует ranges и atomic-writes settings | 1 с | last-write-wins UI | Оставить предыдущие settings |

## Turn state machine

Idle → Snapshotting → Generating → Validating → Preparing → AwaitingCommit → Committing → Completed.

Из Generating возможны Interrupted/AuthFailed/UsageLimited/TimedOut. Из Validating/Preparing/Committing — RolledBack → Repairing, только если error repairable и лимит не исчерпан. Cancellation barrier проверяется при каждом переходе и непосредственно перед commit.

Каждый document имеет один serialized reducer. Attempt получает monotonically increasing epoch; AwaitingCommit создаёт one-shot commit lease. Любое событие с чужим turn/epoch/lease игнорируется и журналируется. Completed, Interrupted, AuthFailed, UsageLimited, TimedOut, Stale, Failed являются absorbing states.

| Current state | Event | Next/effect |
|---|---|---|
| Snapshotting–Preparing | Stop/Timeout/DocumentClose | terminal; invalidate epoch; discard prepared payload |
| Generating | Interrupt acknowledged | Interrupted; late items ignored |
| Generating | PlanReceived | Validating только если epoch current и deadline active |
| Validating/Preparing | RepairableError | RolledBack → Repairing при новом snapshot и неповторяющемся hash |
| Any pre-commit | Selection/DocumentChanged | пометить snapshot stale; AwaitingCommit не выдаёт lease |
| AwaitingCommit | IdleCallback | Committing только после atomic consume lease и fresh checks |
| AwaitingCommit | Stop/Timeout | terminal; revoke lease |
| Committing before native call | Stop | rollback/no-op; terminal |
| Committing between native calls | Stop | cancellation flag; закончить текущий call, rollback own record |
| Committing after verified EndUndo | Stop | Completed; результат уже atomic, пользователь может Undo |
| Terminal | Любой late event/callback | no-op + diagnostic |

Exhaustive reducer tests переставляют Stop, timeout, plan, interrupt acknowledgement, document close, Idle callback и native completion. Один Codex process обслуживается correlation ids; out-of-order notifications никогда не выбирают active document сами.

## Codex conformance trigger

Startup выполняет быстрый schema/hash check. Refresh/Install запускает полный smoke sequence: initialize → account/read → model/list → thread/start → outputSchema turn → event stream → turn/interrupt → thread/resume. User turn блокируется при missing method/event, publisher/hash mismatch или unsupported protocol matrix. Новый runtime активируется только после smoke; failed staging удаляется.

## Несколько Rhino processes

Process singleton относится только к одному Rhino process. Shared LocalAppData пишет под user-scoped named mutex и optimistic generation check. Document binding дополнительно содержит processInstanceId; один mutable binding не resume одновременно в двух processes. Runtime directories immutable и могут читаться совместно; installation activation получает отдельный global user lock.

## Ночной режим

Отсутствует. RhiGhAI не запускает schedule/sleep-time jobs, не обучается на истории и не работает при закрытом Rhino. Все действия имеют явный user/host trigger.
