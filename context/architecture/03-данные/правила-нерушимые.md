# Правила, которые НИКОГДА не должны нарушаться

## Идентичность и версии

- Каждый persisted record содержит schema/state version и стабильный id.
- Неизвестная будущая версия читается fail-closed; destructive downgrade запрещён.
- EventEnvelope append-only; исправление создаёт новое событие, не переписывает прошлое.
- DocumentBinding не угадывает идентичность при Save As/Copy/Recovery ambiguity.

## Trust boundary

- TaskPlanEnvelope всегда недоверенный, даже после output schema Codex.
- Только прошедший schema parsing и semantic validation plan компилируется в OperationNode graph.
- Никакой текст Codex не исполняется как C#, Python, Rhino command, shell, file или network action.
- ModelReference разрешается только через selection текущего snapshot либо current-conversation ownership.

## Host и транзакции

- Один Turn имеет ровно один targetHost: Rhino или Grasshopper.
- Один Attempt не открывает Undo одновременно в RhinoDoc и GH_Document.
- Успешный Turn создаёт ровно один пользовательский Undo record выбранного host.
- Неудачный/остановленный Attempt оставляет host state, layers, attributes, geometry, GH ports и wires эквивалентными before state.
- Commit выполняется только на host UI thread после повторной проверки active document, target, cancellation и всех fingerprints.
- Commit lock допускает не более одного RhiGhAI commit на документ.
- Journal проходит только prepared → committing → committed либо rolledBack; незавершённый committing требует startup reconciliation.

## Commit protocol

1. Build/validate PreparedChange вне host document.
2. Записать и flush durable prepared journal с preimages и intended mutation sequence.
3. На UI thread повторно проверить document identity, target, epoch, commit lease, cancellation и fingerprints.
4. Открыть ровно один host Undo record и записать его identity.
5. Выполнить ordered native mutations, журналируя созданные ids.
6. Проверить postconditions и after signature.
7. Закрыть Undo record; проверить, что его identity принадлежит attempt.
8. Записать verified ExecutionResult и committed journal.
9. Только затем обновить ownership и UI success.

При ошибке до шага 7 rollback выполняется только в том же serialized UI callback: закрыть собственный record, убедиться в его identity, выполнить один host Undo и сверить before signature; при несовпадении остановить commits и показать blocking recovery. После process crash blind Undo запрещён: committing journal обозначает uncertain state и требует диагностики, поскольку пользователь мог изменить документ.

## Геометрия и единицы

- Каждая физическая величина хранит объявленную unit semantics до явного преобразования в document units.
- NaN, Infinity, нулевая/отрицательная размерность там, где требуется положительная, запрещены до RhinoCommon.
- Operation graph ацикличен, имеет ограниченное число nodes/objects/faces и не содержит unknown kind.
- Expected output type/count/topology проверяется до публикации результата.

## Selection и ownership

- Существующий Rhino object изменяется только при явном intent и наличии в актуальном selection.
- Owned object может меняться в follow-up только пока его current fingerprint совпадает с ownership binding.
- Ownership записывается только после успешного host commit.
- Codex thread id, auth tokens и transcript не записываются в 3dm или gh.

## Grasshopper

- Один Conversation владеет не более чем одним RhiGhAI Parametric component.
- New conversation не присваивает себе компонент предыдущего conversation.
- Port identity основана на portId, не на имени или позиции.
- Component state содержит весь алгоритм для solve без Codex и проходит versioned migration при reopen.
- Bake является отдельным явным Rhino action и не вызывается Codex Grasshopper turn.

## Retry и остановка

- RetryMax находится в диапазоне 1–5, timeout — 30–600 секунд.
- Auth, entitlement/usage, cancellation, timeout, stale state и unsupported intent не retry.
- Одинаковая пара planHash/errorCode не выполняется повторно.
- Общий deadline не сбрасывается при repair.
- После Stop ни один ещё не начатый commit не может стартовать.

## Секреты и диагностика

- Credentials и refresh tokens принадлежат Codex runtime и не копируются RhiGhAI.
- Logs не содержат auth URL tokens, credentials, полный prompt, geometry payload или полный document path без redaction.
- AccountSnapshot является отображаемым cache, а не источником прав или billing guarantees.

## Версии и миграции

- External app-server envelope допускает новые optional fields, но не unknown method/event.
- TaskPlan и OperationNode не допускают unknown field/kind.
- Graph, EventEnvelope, settings, journal, GH component state, algorithm и ports versioned независимо.
- Reader поддерживает current и previous version; migration идёт строго по одному шагу.
- Writer всегда пишет current version; неизвестное future state помещается в quarantine.
- Failed migration не изменяет исходный файл/definition и не запускает host commit.
