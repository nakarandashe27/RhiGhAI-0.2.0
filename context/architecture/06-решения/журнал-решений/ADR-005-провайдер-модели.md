# ADR-005 — Сменный провайдер модели

- **Дата:** 2026-08-25
- **Статус:** принято
- **Решение:** планирование идёт через интерфейс `IPlanProvider`. Реализаций две: `CodexPlanProvider` (прежний pinned runtime и вход ChatGPT) и `OpenAiCompatibleProvider` (любой OpenAI-совместимый `/chat/completions` с API-ключом). Провайдер выбирается в настройках, ключ хранится зашифрованным DPAPI для текущего пользователя Windows.
- **Причина:** лимиты ChatGPT/Codex заканчиваются в самый неподходящий момент, и работа плагина не должна зависеть от одного поставщика. Один OpenAI-совместимый клиент покрывает OpenAI, OpenRouter, DeepSeek, Groq, Together, слой совместимости Anthropic и локальные Ollama/LM Studio — отдельные адаптеры под каждого не нужны.
- **Последствия:**
  - ADR-004 (`no API key`) отменён в части запрета ключей; всё остальное про Codex-runtime остаётся в силе.
  - Structured output запрашивается как `response_format: json_schema` (strict); при 400/422 один раз повторяем в `json_object` со схемой в тексте — провайдеры без strict-режима остаются рабочими.
  - `reasoning_effort` уходит только когда выбран не `auto`.
  - Каталог моделей читается из `GET /models`; провайдер без каталога работает с идентификатором модели, вписанным вручную.
  - Ключ никогда не попадает в `settings.json`, transcript или diagnostic bundle; в интерфейсе видны только последние 4 символа.
  - Граница доверия не меняется: ответ любого провайдера остаётся недоверенным и проходит ту же semantic validation.

## Последствия ревью 0.2.0 (2026-08-26)

Правки после код-ревью, уточняющие решение, но не отменяющие его:

- **Повтор без схемы сузился.** Раньше любой 400/422 читался как «strict-режим не поддерживается» и оплачивался вторым запросом. Под 400 ходят также неизвестная модель, `reasoning_effort` у модели без reasoning и переполнение контекста. Теперь повтор в `json_object` происходит только если тело ошибки называет `response_format` или `json_schema`; в остальных случаях наружу уходит исходная ошибка. Если повтор всё же случился и тоже упал, сообщение первой ошибки прикладывается ко второму — раньше оно терялось.
- **401/403 больше не поднимает `Ready`.** Отказ по ключу отличается от «каталога моделей нет»: раньше просроченный ключ вместе с вписанной вручную моделью давал `[ ПОДКЛЮЧЕНО ]` и активную кнопку отправки.
- **`http` разрешён только для loopback.** Ключ уходит на каждом запросе, поэтому для внешнего адреса требуется `https`; проверка стоит и в `RhiGhAISettings.Validate`, и в провайдере.
- **Заголовки Anthropic отправляются только Anthropic-адресам.** `x-api-key` и `anthropic-version` больше не прикладываются ко всем провайдерам подряд.
- **Ключ можно удалить из интерфейса.** Пустое поле по-прежнему значит «оставить сохранённый», а удаление выполняет отдельная кнопка — ветка `SecretStore.SaveApiKey(null)` была недостижима из UI.
- **Текст ошибки провайдера маскируется перед лентой и transcript.** Обещание «ключ не попадает в transcript» опиралось на то, что RhiGhAI его туда не кладёт; шлюзы, возвращающие заголовки запроса эхом в теле ошибки, существуют, а `ProviderException.Message` несёт до 400 символов сырого тела.
- **`provider` пишется в `settings.json` строкой.** Числовое представление молча переинтерпретировалось бы при добавлении члена перед `Codex`; ранее записанные числа продолжают читаться.
- **Адрес API нормализуется через `UriBuilder`.** Конкатенация строк теряла путь и query у адресов вида `https://gw.example/v1?tenant=x`.
