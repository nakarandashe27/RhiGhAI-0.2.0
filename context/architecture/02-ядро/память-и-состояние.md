# Где живёт память

RhiGhAI не строит собственную «память агента» поверх геометрии. Смысл разговора хранит Codex thread, а локальное состояние содержит только то, что нужно для безопасного продолжения и восстановления UI.

## Слой 1. Сейчас

На каждый turn заново собираются:

- prompt и выбранные model/reasoning/target;
- runtime identity активного RhinoDoc и GH_Document;
- units, absolute/angle tolerance, active layer и компактный layer catalog;
- selection: GUID, тип, layer, bounding box, geometry/runtime signature и attributes signature;
- references на RhiGhAI-owned объекты текущего разговора;
- список разрешённых capabilities, лимиты сложности и версия TaskPlan schema;
- correlation id, cancellation state и номер attempt.

Ограничения MVP:

- prompt до 16 000 символов;
- не более 100 target objects в snapshot; больше — явный отказ сузить выделение;
- полный список максимум 200 слоёв, далее active/referenced layers и агрегированная статистика;
- никакой полной сериализации Brep/Curve в prompt: только тип, размеры, topology summary, GUID и fingerprint;
- неизвестные/слишком большие поля выкидываются до отправки, а не после.

Первым удаляется декоративный context и UI transcript. Selection, units, permissions, fingerprints и schema никогда не урезаются молча.

## Слой 2. Недавнее

- Codex хранит turns/items внутри активного thread.
- RhiGhAI хранит локальный redacted EventEnvelope JSONL для восстановления ленты и диагностики.
- В UI загружается текущий conversation; подробные protocol events сворачиваются в stage summary.
- Debug events старше 30 дней удаляются при старте; успешные transcript summaries текущего conversation сохраняются, пока binding активен.
- Новый разговор создаёт новый conversation/thread и не наследует ownership старого.

Недавнее не суммаризируется LLM и не переносится по расписанию: это исключает накопление выдуманных фактов.

## Слой 3. Постоянное

Локальные versioned JSON records в профиле RhiGhAI:

- settings: retry, timeout, last model/effort/target и UI state;
- pinned runtime manifest и protocol compatibility result;
- document identity ↔ active conversation ↔ Codex thread;
- ownership bindings Rhino object ids и GH component instance id;
- compact transcript summary и last successful turn;
- schema/component-state versions и migration markers.

Пишет только RhiGhAI Core через atomic replace. Читают startup/session services. Thread id не записывается в 3dm; serialized GH component содержит только исполнимый algorithm state, порты и собственный conversation ownership id, но не Codex credentials/history.

При Save As/Copy identity не угадывается: ambiguous binding создаёт новый conversation до явного продолжения.

## Document identity state machine

Состояния:

- Unsaved — новый документ без устойчивого path; binding живёт только по runtime serial.
- Opened — файл открыт по canonical path, fingerprint записан.
- Saving — временная блокировка identity transition.
- SavedAs — Rhino сообщил Save As; новый path получает новый documentKey и по умолчанию новый conversation.
- ExternallyCopied — одинаковый content fingerprint обнаружен у другого path без наблюдаемого Save As; всегда новый conversation.
- Recovered — recovery/autosave; новый conversation до явного подтверждения пользователем.
- Missing — прежний path отсутствует; binding не переносится на похожий файл.
- Ambiguous — противоречивые path/fingerprint/process observations; resume заблокирован.

Переходы New/Open/Save/Save As/Rename/Copy/Recovery проверяются matrix tests. Два Rhino processes имеют разные runtime instance ids и не могут одновременно владеть одним mutable binding без user-scoped lock. Без embedded id в 3dm внешнюю копию надёжно распознать невозможно — это принятое ограничение, а не эвристика.

## Слой 4. Навыки

Автоматического обучения в MVP нет. Процедурная память — это versioned capability registry в коде, schemas, fixtures и tests. Ошибки пользователя не превращаются в новые способности автоматически.

## Когда недавнее переезжает в постоянное

Только детерминированными событиями:

- успешный commit обновляет ownership и last successful turn;
- успешный start/resume обновляет active thread binding;
- Save/Save As обновляет document identity по явной policy;
- изменённые settings записываются после Save and close.

## Когда постоянное очищается

- Logout очищает auth через Codex, но не удаляет геометрию или thread mapping.
- Uninstall/явная очистка локальных данных удаляет settings, logs, mappings и managed runtime.
- Binding с отсутствующим файлом не перепривязывается автоматически; он может быть убран обслуживанием после 90 дней, если не является active.
- Commit journal со статусом committing никогда не удаляется до startup reconciliation.

## Layout, locking и recovery LocalAppData

- Runtime: immutable version directories + active manifest.
- Settings: singleton с checksum, generation и backup.
- Document mappings: один versioned store под user-scoped named mutex.
- Transcript: отдельный JSONL на conversation; single-writer lock, повреждённый tail обрезается до последней checksum record.
- Commit journal: отдельный файл на attempt, durable flush до host mutation.

Все пути строятся RhiGhAI, а не входом модели. Junction/symlink/reparse target за пределами RhiGhAI root отклоняется. Corrupt store переносится в quarantine: transcript не блокирует работу, mapping начинает новый conversation, runtime manifest откатывается, committing journal блокирует model mutation и показывает recovery warning.
