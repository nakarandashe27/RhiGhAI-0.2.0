# Что сознательно не выбрано

## Полный fork RhinoMCP

Его router/MCP/arbitrary tools и свободный GH graph противоречат строгому executor contract. Берём только отдельные MIT-паттерны после проверки и атрибуции.

## Произвольное выполнение C#, Python или Rhino commands

Невозможно надёжно ограничить, остановить и fault-injection проверить. Показанный C# остаётся representation canonical graph.

## OpenAI API key и прямой Responses API

Нарушает пользовательский контракт и создаёт отдельный billing/auth UX. Используем managed ChatGPT login app-server.

## WebSocket, loopback HTTP и MCP-router

Для одного Rhino process stdio проще, не открывает port и уменьшает число failure modes. WebSocket app-server остаётся experimental.

## WPF, WinForms и встроенный браузерный UI

Eto уже является штатным UI Rhino. Browser нужен только внешнему OAuth flow; WebView добавил бы runtime, accessibility и DPI риски.

## SQLite/PostgreSQL/векторная база

Объём локальной памяти мал, semantic search отсутствует, server concurrency нет. Versioned JSON/JSONL проще посмотреть, мигрировать и восстановить.

## Generic JsonSchema.Net runtime

TaskPlan schema мала и принадлежит RhiGhAI. Strict DTO + structural checks + semantic validator дают нужную гарантию без дополнительной dependency и её licensing/version surface.

## Dependency injection container и event-bus framework

Composition root и typed interfaces достаточны для четырёх assemblies. EventEnvelope не требует инфраструктурного broker.

## Background Windows service и sleep-time agent

RhiGhAI работает только вместе с открытым Rhino и явными host/user triggers. Service усложнил бы install, credentials и recovery.

## net48 и Rhino /netfx

MVP требует Rhino 8.20+ на .NET 8. Multi-targeting удвоил бы compatibility matrix без пользовательской ценности.

## Rhino 9 / Grasshopper 2

Это другой host/API target. Сначала доказываем Rhino 8/GH1; новый major потребует отдельного compatibility decision.

## Свободная генерация Grasshopper-графа

Граф трудно атомарно менять, сериализовать и поддерживать. Один owned component даёт parameterization с контролируемым state.

## RHI как публичный канал

RHI оставляем только для личного MVP: McNeel рекомендует Package Manager. Публичный релиз готовится как Yak после signing и clean-machine matrix.

## Автообновление runtime и плагина

Новая версия не заменяет last-known-good до explicit compatibility test. Плагин MVP обновляется установочным пакетом, а не self-modifying code.

## CDN-шрифты и remote UI assets

Rendering интерфейса не зависит от сети или сторонней доступности. Asset встраивается только после подтверждения права распространения.
