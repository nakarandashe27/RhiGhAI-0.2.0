# Технологический стек

Проверено по официальной документации 24 августа 2026 года. Точные package/runtime versions фиксируются lock-файлами после прохождения compatibility spikes; latest автоматически не подхватывается.

## Структура solution

- RhiGhAI.Core — contracts, graph, validation, orchestration, persistence, Codex adapter abstractions.
- RhiGhAI.Rhino — RHP entrypoint, panel, Rhino snapshot/executor/transaction, commands.
- RhiGhAI.Grasshopper — GHA assembly, Parametric component, serialization, solve, preview, bake, GH Undo.
- RhiGhAI.Tests — pure .NET contract/state-machine/validator/renderer tests.
- RhiGhAI.HostTests — запускаемые при установленном Rhino fault-injection и GH round-trip tests.
- packaging — RHI/Yak manifests, SHA manifest и installer assets.

## Контракт совместимости Codex

Совместимость задаётся тройкой plugin version × Codex runtime version × generated protocol schema hash. Для каждой поддерживаемой тройки хранятся:

- exact binary version, download URL, SHA-256 и publisher identity;
- generated app-server JSON schemas и recorded JSONL fixtures;
- обязательные initialize/account/model/thread/turn methods и events;
- допустимые optional fields и явно unsupported experimental capabilities;
- результат conformance smoke-test и дата проверки.

Startup разрешает user turn только после initialize, account/read, model/list и schema compatibility. Install staging дополнительно проверяет start/resume thread, outputSchema turn, streaming и interrupt. Новая версия активируется immutable directory switch только после полного smoke-test; иначе остаётся last-known-good.

RhiGhAI не включает apps, MCP, skills и dynamic tools. Thread запускается в отдельном пустом cwd и isolated Codex home, с environments = empty, approvalPolicy = never и read-only permission profile. Любой tool-call item считается нарушением planning-only режима: turn прерывается и plan отклоняется. Это ограничивает, но не заменяет OS sandbox; runtime gate проверяет фактическое поведение закреплённой версии.

## Версионирование контрактов

- App-server outer envelopes читаются tolerant version-specific reader: неизвестные optional fields сохраняются/игнорируются, но unknown method/event отклоняется allowlist.
- TaskPlan использует строгий discriminated union: unknown kind/field/version fail-closed.
- Operation graph, EventEnvelope, settings, journal и GH component/port schema имеют независимые версии.
- Persistent state поддерживает только последовательный read N/N-1 → migrate → write current. Skip migration запрещён; future version уходит в quarantine без перезаписи.
- Для каждой версии хранится golden JSON corpus с upgrade/downgrade/unknown-field tests.

## Хранение и межпроцессная блокировка

LocalAppData разделён на stores с разной durability: settings, document mappings, transcripts, commit journals, runtime manifests и immutable runtime directories. Shared write берёт user-scoped named mutex и проверяет generation/version перед replace. Запись: temp в том же volume → flush → checksum → atomic replace → last-known-good backup. Transcript можно отбросить; corrupt mapping создаёт новый conversation; corrupt committing journal блокирует новые commits до reconciliation.

## Installation trust chain

Runtime принимается только из зафиксированного официального source с проверенными license/redistribution terms, Authenticode publisher и SHA-256 manifest. Installer/assemblies подписываются перед внешним распространением. Download идёт в staging, Mark-of-the-Web и Defender не обходятся; activation immutable и обратима. При блокировке UI показывает точную причину и официальный recovery path без shell. Clean Windows 11, standard user, Defender/SmartScreen on — release gate.

## Зафиксированные официальные основания

- [OpenAI Codex app-server](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md): initialization, version-matched schema generation, threads/turns, outputSchema, streaming, interrupt, account/model/rate-limit methods.
- [Rhino: Moving to .NET Core](https://developer.rhino3d.com/guides/rhinocommon/moving-to-dotnet-core/): Rhino 8.20 defaults to .NET 8; recommended target net8.0.
- [Rhino panels](https://developer.rhino3d.com/api/RhinoCommon/html/M_Rhino_UI_Panels_RegisterPanel.htm): Eto Control can be registered as a native Rhino panel.
- [Rhino modeless Undo](https://developer.rhino3d.com/api/rhinocommon/rhino.rhinodoc/beginundorecord): BeginUndoRecord supports changes from modeless UI.
- [Grasshopper variable parameters](https://developer.rhino3d.com/api/grasshopper/html/M_Grasshopper_Kernel_IGH_VariableParameterComponent_VariableParameterMaintenance.htm): maintenance participates in Open/Paste/Undo/Redo lifecycle.
- [Grasshopper Undo](https://developer.rhino3d.com/api/grasshopper/html/Methods_T_Grasshopper_Kernel_Undo_GH_UndoServer.htm): one record can contain the component actions.
- [Rhino package guidance](https://developer.rhino3d.com/guides/rhinocommon/plugin-installers-windows/): RHI is simple but no longer actively developed; public distribution should move to Package Manager.

## Экспериментальные жетоны

1. Codex app-server adapter и managed runtime pin.
2. Versioned dynamic GH component с собственным algorithm graph и exact Undo.

Третий жетон не тратим: UI, storage, JSON, async и packaging используют штатные технологии.
